1. System Concept, Scope & Academic Disclosures

The AI-Powered Real-Time Collaborative Workspace with Predictive Analytics is a multi-tenant full-stack productivity web application designed to unify Agile task tracking, real-time messaging, rule-based AI text assistance (with optional Gemini API support), secure file handling, and proactive machine learning risk prediction. Developed by Shivashankargoud B R (Reg No: KUB25MCA019) at Kishkindha University, the project demonstrates decoupled microservices interacting through REST and WebSocket interfaces.

Academic Disclosures & Project Scope Clarification

1. Synthetic Data Disclosure: The machine learning dataset consists of 3,000 synthetically generated task records. Model performance scores reflect learning capability on rule-based probabilistic data rather than measured production team dynamics.
2. AI Assistance Disclosure: AI-assisted development tools were utilized during development for code structuring, debugging, and documentation generation. In the running demo (GEMINI_API_KEY unset), the assistant executes rule-based extractive summarization and heuristic action-item extraction.
3. Project Scope Clarification (Real vs Planned): To ensure thorough delivery and testing of multi-tenancy, machine learning, and real-time chat within the solo timeframe, collaborative rich-text editing via CRDT / Yjs, multi-language localization, RAG search over uploaded files, and concurrency load testing were deferred to future work, and mobile access is delivered as a PWA rather than a compiled native APK. The documents table remains reserved in PostgreSQL.

4. Multi-Tenant Isolation & Role Hierarchy Implementation

Multi-tenant isolation is enforced in PostgreSQL-backed Express middleware and our shared workspace-resolution helper, rather than relying on JWT claims or database triggers.

Exact Authentication, Rate Limiting & Isolation Flow

  1. Authentication (requireAuth in server/src/middleware/auth.js):
    • Extracts Authorization: Bearer <token> header and verifies signature via JWT_ACCESS_SECRET.
    • JWT holds only decoded.userId (never org_id). Looks up SELECT id, name, email, avatar_url FROM users WHERE id = $1 and sets req.user.
    • server/src/routes/auth.js applies express-rate-limit to /login and /register with skipSuccessfulRequests: true (max: 20 in production / 60 in development per 15 min) so repeated failed attempts block with HTTP 429 without locking out valid logins.
  2. Organization & Analytics Authorization (requireRole(minimumRole)):
    • Reads target orgId from params, body, query, or x-org-id header, then checks PostgreSQL: 
      SELECT role FROM organization_members WHERE org_id = $1 AND user_id = $2
    • The client-supplied org ID is never trusted until membership confirms; non-members get HTTP 403 Forbidden. Evaluates role hierarchy (member: 1, manager: 2, admin: 3) and attaches req.userOrgRole and req.orgId.
  3. Task, Chat, File & Socket Isolation (resolveAuthorizedResource in server/src/utils/tenantAccess.js):
    • Applied across every route in taskController.js, chatController.js, fileController.js, and Socket.IO chatSocket.js (on channel:join, every message:send, and typing:*).
    • Resolves the organization through the resource's workspaces.org_id join in PostgreSQL (never reading client-supplied orgId), verifies organization_members, and returns HTTP 404 across tenants so existence isn't leaked.

6. Rule-Based AI Assistant (+ Optional Gemini) & File Upload Subsystems

Two auxiliary subsystems in server/src/controllers/:

1. AI Assistant (aiController.js / routes/ai.js)

  • Endpoints: POST /api/ai/summarize and POST /api/ai/action-items (JWT-protected; checks organization_members if document_id is passed).
  • Active Behavior: Because GEMINI_API_KEY is empty in the demo .env, it executes rule-based extractive summarization (Local Extractive Engine) and heuristic action-item extraction (Heuristic Engine), using boundary-aware splitting (/\n+|(?<=[.!?])\s+/) so decimals such as 89.3% stay intact. When a server-side GEMINI_API_KEY is set, it calls Google Gemini through the API.
  • Automated Testing: Verified in server/test_ai.js across 4 checks.

2. Secure File Repository (fileController.js / routes/files.js)

  • Endpoints: POST /api/files/upload | GET /api/files/workspace/:workspaceId | GET /api/files/:fileId/download.
  • Implementation: Uses multer@2.5.0 disk storage with sanitized unique filenames and MIME whitelist. Enforces workspace-to-organization membership via tenantAccess.js across upload, listing, and download (with temp file cleanup on rejected uploads and no hardcoded orgId = 1 fallback).
  • Automated Testing: Verified in server/test_files.js (4 checks) and server/test_tenant_tasks.js (Check 4: cross-tenant spoofed upload/list/download rejected 404, owner download 200).

7. Progressive Web App (PWA) Implementation & Mobile Controls

  • Web App Manifest (manifest.json): Configured with "display": "standalone", "theme_color": "#0284c7", "background_color": "#ffffff", linking icon-192.png and icon-512.png.

13. Viva Voce Oral Defense Playbook & Model Answers

Q1: How do you enforce multi-tenant isolation?

Answer: "The JWT carries only userId. On org and analytics routes, requireRole checks organization_members and returns HTTP 403 on mismatch. On tasks, chat, files, and Socket.IO (channel:join and every message:send), our shared helper resolveAuthorizedResource in tenantAccess.js resolves organization ownership through the resource's workspace in PostgreSQL — never trusting client org IDs — and returns HTTP 404 across tenants. My own cross-tenant test caught a 0-of-5 gap earlier, and now passes 5 of 5."

Q2: Why did Logistic Regression score higher than Random Forest in CV?

Answer: "On our 3,000-record synthetic dataset, Logistic Regression scored 90.17% (±0.97%) vs Random Forest 89.03% (±1.03%) because the synthetic rule formula was largely linear. I kept Random Forest for its feature importance rankings and ability to model non-linear interactions, and I would benchmark both again on real team data."

Q3: What does the AI Assistant do without an API key, and why doesn't sw.js cache API calls?

Answer: "With GEMINI_API_KEY unset, the assistant runs rule-based extractive summarization and heuristic action-item extraction (switching to Google Gemini via API when configured). Meanwhile, sw.js caches only the static app shell and skips all /api routes so live data always comes fresh from PostgreSQL."

Q4: How is brute-force protection tested and handled without locking out demos?

Answer: "Passwords use bcryptjs with 12 salt rounds, and routes/auth.js uses express-rate-limit with skipSuccessfulRequests: true. Back-to-back runs proved HTTP 429 blocks bursts while allowing legitimate logins through."
